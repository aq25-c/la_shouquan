# 授权许可系统（License Server）

一套自托管的软件授权系统：**客户注册 · CDK 激活 · 授权到期控制 · 离线许可证签名 · Web 管理后台 · Docker 一键部署**。

被授权的客户端可以是你写的任何程序（C/C++、C#、Go、Python、Electron…），只需要能发 HTTP 请求、能做一次 Ed25519 验签。

- **运行时零依赖**：只用 Node 内置模块（`node:sqlite` / `node:crypto` / `node:http`），不需要 `npm install`，不需要外部数据库。
- **单容器部署**：Docker Compose 一条命令起服务，数据全在 `./data` 目录，备份就是拷目录。

## 核心概念

| 概念 | 说明 |
| --- | --- |
| **产品（Product）** | 你要授权的软件，例如 `app-pro`。客户端用产品编码识别。 |
| **模块（Module）** | 产品内的功能单位，例如 `core`、`report`。**CDK 绑定的就是模块组合**，客户端据此判断某功能是否被授权。 |
| **CDK** | 卡密（兑换码），形如 `Q3GP-2WUW-7RFC-XPY2`。后台批量生成，一次性核销。 |
| **客户（Customer）** | 激活时自动创建或注册的账号，可登录查看/自助解绑。也支持匿名激活。 |
| **授权（License）** | CDK 核销后产生的授权记录，决定**到期时间**、**席位（可绑定设备数）**、**模块范围**。 |
| **设备（Device）** | 一台机器（客户端上报的稳定指纹）。每个授权最多绑定 `seats` 台。 |
| **许可证文件** | 服务端用 Ed25519 签名的字符串，客户端**离线**即可验签 + 校验到期 + 校验设备绑定。 |
| **代理（Channel）** | 分销来源（如"淘宝旗舰店""代理商 A"）。CDK 批次可归属代理并带结算单价，激活后落到授权上，用于按代理统计销量与营收。未归属代理即为「直销」。 |
| **试用（Trial）** | 一种授权类型（`kind = trial`）。客户登录后可自助开通，天数/席位/次数由后台试用配置决定；到期控制、设备绑定、心跳与正式授权完全一致，只是不计营收。 |

授权校验采用「混合模式」：

```
首次激活（联网）────────────▶ 得到 license_key + 许可证文件（签名，含离线有效期）
                                        │
客户端日常使用 ── 本地验签（离线，无需联网）◀┘
                                        │
每 24h 心跳（联网）─────────▶ 服务端重新签发文件，滚动续期；
                              断网超过 OFFLINE_GRACE_DAYS 天 → 本地验签失败 → 降级
```

离线有效期 = `min(授权真实到期时间, 当前时间 + OFFLINE_GRACE_DAYS 天)`，所以**断网不会永久白用，吊销/到期也能在宽限期后生效**。

## 功能清单

**授权与到期控制**
- 授权有效期按天数签发，到期状态由服务端动态判定（无需定时任务）
- **模块级到期**：每个模块有自己的到期时间与计费类型；同一客户再次购买时，同一个模块从它自己的到期时间往后叠加，新模块从购买当天起算，本次 CDK 未涉及的模块完全不动
- **到期是软状态**：模块全部到期后账号仍可登录、授权信息仍可读取，只是功能不可用（心跳不再返回 403）
- **席位是软件级的**：一条授权 = 一个软件，席位决定这个账号能同时登录几台设备；模块只是功能开关，不参与席位
- **并卡取较大值**：同一客户再买一张卡并入现有授权时，席位取「原席位」与「新卡席位」的较大者——新卡的承诺一定生效，续费也不会把席位翻倍
- **全部过期后重新激活**：席位按新卡从默认值（1）起算，不继承旧授权的席位数
- **到期自动解绑设备**：授权自然到期后，绑定的设备全部释放、席位不再被占用；续费后同一台机器下次心跳会自动回来，手动解绑的设备不会自己复位
- 后台可随时：直接改到期时间、按天延长（可负数缩短）、暂停、恢复、吊销
- 吊销/暂停后，客户端下一次心跳即被拒绝（宽限期内离线仍可用，属预期行为）；自然到期不拒绝心跳，只关功能

**CDK 管理**
- 批量生成（一次最多 5000 个），码表去掉易混字符 `I O 0 1`，格式 `XXXX-XXXX-XXXX-XXXX`
- 每个 CDK 绑定：产品 + 模块组合 + 授权天数 + 席位数 + 可选兑换截止时间
- 一次性核销（并发安全），可按批次筛选、复制、导出 CSV（带 BOM，Excel 直接打开）
- 未使用的 CDK 可作废

**账号**
- 客户注册/登录（scrypt 口令哈希），登录后可查看授权、自助解绑设备、重置许可证密钥
- 也支持不带账号的匿名激活
- 管理员登录 + 多管理员 + 改密（改密后旧会话立即失效）

**删除客户（硬删除）**
- 仅超级管理员可操作，员工和代理都不行
- 前置条件：名下授权**全部已过期或已吊销**才允许删除；仍在有效期内、或处于暂停状态的授权会拦住，并逐条说明是哪张授权、什么原因
- 删除范围：客户、名下授权、授权下的设备、模块记录，以及**关联的 CDK**；客户会话立即失效
- CDK 删行，但码、批次、激活时间都已写进删除快照，事后仍能查到是哪个码被删了
- 删除前把完整快照写进审计日志（`action=customer.delete`），包含客户资料、每条授权的单号/模块/到期/状态、每台设备、每张 CDK；**快照写入与删除在同一个事务里，日志落不了盘就整体回滚**。快照不含密码哈希与密钥哈希
- 删除后代理的历史营收会相应减少（营收按已激活授权数计算）

**设备席位**
- 每个授权限制可绑定设备数，席位满时返回 `SEAT_LIMIT`
- 后台/客户均可解绑设备实现换机

**代理 / 分销**
- 代理档案（编码/名称/联系人/电话/邮箱/备注），可停用；被 CDK 或授权引用时禁止删除
- CDK 批次可归属代理并设置结算单价（单位：分）
- 客户端激活时自动继承代理与单价，销售链路可追溯
- 按代理聚合：CDK 生成/核销数、激活率、授权数与有效数、近 30 天新增、营收（累计与近 30 天）、续费次数
- 授权与 CDK 列表均可按代理筛选（含「无代理 = 直销」）

**试用**
- **模块级试用配置**：每个模块可以单独设置是否开放试用、试用类型（按天 / 按次数）、试用值、席位数、每客户可试用次数、离线宽限；没配的字段回落到产品级、再回落到全局
- 全局 / 产品级配置仍然有效，作为模块的默认模板
- 客户登录后可自助开通试用，可指定模块；每个模块按自己的次数上限独立计数
- 试用授权与正式授权共用一套到期控制：可延长试用、可吊销、可按 `kind=trial` 单独筛选
- 后台展示试用统计：试用总数、有效数、试用后转正式的客户数

**界面（手机 / 平板 / 桌面）**
- 登录页改左右分栏：左侧品牌与卖点，右侧表单；手机上收成单列，品牌区变顶部色块
- 登录支持「记住邮箱」和密码显示切换
- 手机端侧边栏收成抽屉（汉堡按钮打开，点遮罩或选择菜单自动收起），不再挤占顶部空间
- 手机端表格自动转成卡片：表头文字变成每行的字段标签，9 列的授权表也不用横向拖
- 弹窗在手机上全屏显示，底部按钮吸底并按两列排布，避免误触
- 列表里的客户一栏改为**姓名优先、邮箱做副行**，匿名激活单独标注
- 导航图标换成内联 SVG，不依赖系统 emoji 字体，各平台显示一致

**客户门户（默认入口 `/`）**
- 注册 / 登录，**注册成功直接进授权信息**，不用再跳一次
- 授权信息：账号、每个产品的授权状态与到期、**模块明细**（每个模块到期 / 剩余 / 次数额度）、席位占用、已登录设备
- 激活：输入激活码先**查询**（产品、时长、席位、模块，不核销），确认后再激活
- **网页激活只把卡绑到账号，不占设备席位**（`bind_device=false`），席位留给客户端首次启动时绑
- 手机 / 平板 / 桌面三档自适应：桌面左右分栏，手机单列卡片，表格与按钮按触屏尺寸放大
- 管理后台走**可配置的隐藏入口**（默认 `/upadmin`），后台「设置与公钥 → 系统入口」可改，改完立即生效、旧地址失效

**安全**
- 许可证 Ed25519 签名（私钥只存服务端，公钥内置客户端）
- 管理接口 Bearer 会话鉴权、登录限流、全局限流、审计日志（谁在什么时候改了什么）
- 安全响应头、SQL 全参数化、CSV 公式注入防护

## 快速部署

### 方式一：Docker Compose（推荐）

```bash
# 1. 准备配置
cp .env.example .env
#    编辑 .env：至少改掉 ADMIN_PASSWORD

# 2. 起服务（首次会构建镜像）
docker compose up -d --build

# 3. 确认健康
docker compose ps                       # STATUS 应为 healthy
curl http://localhost:6889/healthz
```

打开 `http://<服务器IP>:6889/` 是**客户门户**（注册 / 登录 / 查授权 / 激活）；
管理后台在 `http://<服务器IP>:6889/upadmin`，用 `.env` 里的 `ADMIN_EMAIL` / `ADMIN_PASSWORD` 登录。
后台「设置与公钥 → 系统入口」可以把 `upadmin` 改成别的地址，改完立即生效、旧地址失效。

> 仓库**不附带预构建镜像**：首次 `up --build` 会在这台机器上构建（需要能访问 Docker Hub 拉取 `node:24-alpine`）。
> 内网/离线环境怎么把镜像搬过去（`docker save` / `docker load`、离线基础镜像、私有仓库），见 [docs/DEPLOY.md 第 4.1 节](docs/DEPLOY.md)。

> Linux 上如果容器写 `./data` 报权限错误（容器以 uid 1000 运行）：
> `mkdir -p data && sudo chown -R 1000:1000 data`

### 方式二：纯 docker run

```bash
docker build -t license-server:1.0.0 .
docker run -d --name license-server \
  -p 6889:6889 \
  -v "$PWD/data:/data" \
  -e ADMIN_EMAIL=admin@example.com \
  -e ADMIN_PASSWORD='换成你的强密码' \
  --restart unless-stopped \
  license-server:1.0.0
```

### 方式三：不用 Docker（有 Node ≥ 22.18 即可）

```bash
# 不需要 npm install —— 没有任何第三方依赖
PORT=6889 DATA_DIR=./data ADMIN_EMAIL=admin@example.com ADMIN_PASSWORD='强密码' \
  node src/server.ts
```

启动日志会打印**客户端验签公钥**（也随时可在后台「设置与公钥」查看），把它内置到客户端即可。

> 生产环境部署（HTTPS 反向代理、systemd、备份恢复、升级回滚、故障排查、上线检查清单）请看 **[docs/DEPLOY.md](docs/DEPLOY.md)**。

## 环境变量

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `PORT` | `6889` | 监听端口 |
| `HOST` | `0.0.0.0` | 监听地址 |
| `DATA_DIR` | `./data` | 数据目录（SQLite 库、签名密钥、初始密码文件） |
| `DB_PATH` | `$DATA_DIR/license.db` | 单独指定数据库路径 |
| `ADMIN_EMAIL` | `admin@example.com` | 初始管理员邮箱（仅首次启动创建） |
| `ADMIN_PASSWORD` | 空 | 初始管理员密码；**留空则随机生成**并写入 `$DATA_DIR/initial-admin.txt` |
| `ADMIN_NAME` | `系统管理员` | 初始管理员名称 |
| `OFFLINE_GRACE_DAYS` | `7` | **离线宽限天数**：许可证文件离线可用上限 |
| `HEARTBEAT_INTERVAL_HOURS` | `24` | 建议客户端心跳周期（接口会返回该值） |
| `HEARTBEAT_STALE_HOURS` | `72` | 超过多久没心跳算异常（仅统计，不影响离线验签） |
| `ADMIN_TOKEN_TTL_HOURS` | `12` | 后台会话有效期 |
| `CUSTOMER_TOKEN_TTL_HOURS` | `720` | 客户会话有效期 |
| `RATE_LIMIT_PER_MIN` | `600` | 单 IP 每分钟请求上限，`0` 关闭 |
| `TRUST_PROXY` | `false` | 在 Nginx/Traefik 后面设 `true`（从 X-Forwarded-For 取真实 IP） |
| `MAX_BODY_BYTES` | `262144` | 请求体上限 |
| `SIGNING_PRIVATE_KEY_B64` | 空 | 已有签名私钥（PKCS8 PEM 的 base64），多实例/迁移时用 |
| `TZ` | 容器内 `Asia/Shanghai` | 时区 |

## 后台使用流程

1. **产品与模块**：新建产品（编码用小写，如 `app-pro`），再往里加模块（`core`、`report`…）。
2. **代理**（可选）：新建代理（如「淘宝旗舰店」「代理商 A」），填联系人与备注。
3. **CDK**：选产品 → 勾选模块 → 填天数/席位/数量 →（可选）选**归属代理**并填**结算单价（元）** → 生成。生成结果可一键复制或下载 CSV，交给代理/客户。
4. **客户**（可选）：在「客户」页可**手动新增客户**（邮箱 + 密码，或只填姓名建匿名客户），不必等客户端自己注册。
5. 客户拿到 CDK 后在客户端里激活；也可由你在后台「手动开通」直接给某个邮箱开授权，不走 CDK。
6. **授权**页管理生命周期：查看设备、延长、改到期时间、暂停、吊销、重置设备、重置密钥、重新签发文件。
7. **客户列表调到期**：客户行内「调整到期」→ 勾选要改的授权，按天延长或直接设定日期；客户端下次心跳即同步。
8. **设备换机**：授权详情里可「绑定新设备」，已解绑的设备也能「重新绑定」——**到期时间沿用首次激活，不会重置**。
9. **试用**：在「设置与公钥 → 试用配置」里设定天数/席位/次数，客户登录后即可自助开通试用；到期前可在授权页延长。
10. **代理看板 / 审计日志**：各代理 CDK 核销数、激活率、营收；所有关键操作留痕（谁、什么时候、对哪个对象、IP、变更内容）。

> **营收口径**：`营收 = 已激活授权数 × 批次结算单价`（激活即计入），续费次数单独统计。单价为 0 的批次不计入营收，适合只想区分来源、暂不统计金额的场景。

## 客户端接入（三步）

接口前缀 `/api/v1`，请求/响应均为 JSON。成功响应 `{"ok":true,"data":{…}}`，失败 `{"ok":false,"error":{"code":"…","message":"…"}}`。
完整接口清单见**管理后台 → API 文档**页（由服务端真实路由表自动生成，可搜索、可复制 curl）；接入细节与验签示例见 [docs/client-integration.md](docs/client-integration.md)。

### 1. 激活（用 CDK 换授权）

```bash
curl -X POST http://localhost:6889/api/v1/licenses/activate \
  -H 'Content-Type: application/json' \
  -d '{
        "cdk": "Q3GP-2WUW-7RFC-XPY2",
        "device_id": "PC-OFFICE-01",
        "device_name": "办公室主机",
        "platform": "Windows 11",
        "email": "buyer@example.com",
        "password": "BuyerPass123"
      }'
```

关键返回字段：

```json
{
  "ok": true,
  "data": {
    "license_key": "LK-…",           // 心跳凭证，只返回这一次，务必本地保存
    "license_file": "eyJ2Ijox….MEUCIQ…", // 签名许可证，离线校验用
    "offline_expires_at": "2026-11-19T08:00:00.000Z",
    "expires_at": "2027-11-12T08:00:00.000Z",
    "days_left": 365,
    "module_codes": ["core", "report"],
    "heartbeat_interval_hours": 24
  }
}
```

`email`/`password` 可省略（匿名激活）；带邮箱时若账号不存在会自动创建。若已登录（`Authorization: Bearer <客户token>`）则直接绑到该账号。

### 2. 启动时本地验签（完全离线）

用内置公钥验签 `license_file`，然后检查：`exp` 未过期、`prd` 是自己的产品、`dev` 与本机设备指纹一致、`mod` 包含要用到的功能模块。
详见 [docs/client-integration.md](docs/client-integration.md)，含 C/OpenSSL、Node、Python 三种验签代码。

### 3. 定时心跳（联网续期）

```bash
curl -X POST http://localhost:6889/api/v1/licenses/heartbeat \
  -H 'Content-Type: application/json' \
  -d '{"license_key":"LK-…","device_id":"PC-OFFICE-01"}'
```

返回新的 `license_file`（滚动宽限期）、`expires_at`（= 各模块里最晚的那个）和 `modules[]`（每个模块各自的到期与可用状态）。
- `200`：正常，覆盖本地许可证文件。**到期也是 200**——账号和授权信息照常返回，只是 `expired=true`、过期的模块 `active=false`，客户端据此关掉对应功能即可，不必退出登录
- `403` + `LICENSE_REVOKED` / `LICENSE_SUSPENDED` / `CUSTOMER_DISABLED`：**授权不可用**，客户端应提示并降级/退出（这三类是管理员主动干预，与自然到期不同）
- `404` + `DEVICE_NOT_BOUND`：设备被解绑，需要重新激活
- `404` + `INVALID_LICENSE_KEY`：密钥失效（被重置），需要重新激活

其它常用接口：`POST /api/v1/licenses/enroll`（同授权加绑新设备）、`POST /api/v1/licenses/release`（解绑）、`POST /api/v1/cdks/inspect`（激活前预检 CDK，不核销）、`GET /api/v1/public-key`（取公钥）。

## 授权如何生效与失效

| 场景 | 服务端行为 | 客户端表现 |
| --- | --- | --- |
| 正常 | 心跳返回新许可证文件 | 本地验签通过 |
| 某个模块到期 | 心跳 `200`，该模块 `active=false` | 只有这个模块的功能关掉，其余照常 |
| 全部模块到期 | 心跳 `200`，`expired=true`，所有模块 `active=false` | 仍可登录、仍能拿到授权信息，全部功能不可用 |
| 后台续费 | 心跳返回新 `expires_at` | 下次心跳后自动恢复 |
| 暂停 | 心跳 `403 LICENSE_SUSPENDED` | 同上（宽限期后失效） |
| 吊销 | 心跳 `403 LICENSE_REVOKED` | 同上，且不可恢复 |
| 客户停用 | 心跳 `403 CUSTOMER_DISABLED` | 同上 |
| 设备被解绑 | 心跳 `404 DEVICE_NOT_BOUND` | 需要 CDK 重新激活 |
| 密钥被重置 | 心跳 `404 INVALID_LICENSE_KEY` | 需要用新密钥重新激活 |
| 断网 | ——（心跳失败可忽略） | 宽限期内继续可用，超期后验签失败 |

> 想更严格：把 `OFFLINE_GRACE_DAYS` 调小（如 `1~3`），要求客户端每天联网；想更宽松就调大（如 `30`）。
> 想禁止离线：设 `0`，客户端必须每次心跳拿到新文件才能用。

## 运维：备份、迁移、升级

- **备份**：整个 `./data` 目录（含 `license.db`、`license.db-wal`、`keys.json`）。热备份建议 `sqlite3 data/license.db ".backup 'backup.db'"` 或直接 `docker compose stop` 后拷贝。
- **迁移/多实例**：把 `./data` 拷到新机；或把 `keys.json` 里的私钥通过 `SIGNING_PRIVATE_KEY_B64` 注入（多实例必须共用同一把私钥，否则签发的许可证互通不了）。
- **升级**：`git pull`（或替换 `src/`）后 `docker compose up -d --build`。数据库自动迁移，`data/` 不受影响。
- **换签名密钥**：会导致**所有已签发许可证失效**（客户端内置的公钥对不上），除非同步更新客户端。

### 数据库版本与兼容升级

数据库结构用 `PRAGMA user_version` 标记版本，当前为 **v11**（常量 `SCHEMA_VERSION`，见 `src/db.ts`）。

**升级是自动且向后兼容的**：程序启动时读当前版本，逐级补齐缺失的迁移（v1→v2→…→最新），每一步各自在事务里执行，失败整体回滚，已有数据全部保留。启动日志会写明实际发生了什么：

```
数据库:      /data/license.db（结构版本 v10 → v11（已自动升级），程序支持 v11）
数据库:      /data/license.db（结构版本 v11，程序支持 v11）        # 新库或已是最新
```

**升级前自动备份**：需要升级的是已有数据的库时，会先快照到 `<数据目录>/backups/pre-v<旧版本>-<时间>.db` 再迁移；备份失败只告警、不阻止启动。

**降级保护**：如果库版本**高于**程序支持版本（例如把镜像回滚到旧版），程序拒绝启动并提示：

```
数据库结构版本 v12 高于当前程序支持的 v11：请升级到更新版本的程序，或从备份恢复数据库后再用当前版本启动。
```

避免旧代码写坏新结构。

**开发约定：每次改 schema 必须做满三步**

1. `src/db.ts` 末尾追加 `const SCHEMA_Vx = \`...\`;`
2. `migrate()` 里补一行 `if (version < x) runMigration(db, SCHEMA_Vx, x);`
3. `SCHEMA_VERSION` 常量 +1

⚠️ **不要修改已发布的历史迁移常量**（V1~V8）。新库会从 V1 一路跑到最新，改动历史会让新库与老库走岔路径——本项目就踩过一次（批量改名时误改了历史迁移，导致新库先建出新表、迁移里再 rename 就冲突）。

**回滚到旧版本时**，镜像与数据库必须一起回滚：

```bash
docker compose down
cp data/backups/pre-v7-<时间>.db data/license.db
rm -f data/license.db-wal data/license.db-shm
docker compose up -d
```

只回滚镜像不回滚数据库，会被上面的降级保护拦住（这是有意为之）。

## 常见问题

**Q：客户端换电脑怎么办？**
后台「授权 → 管理 → 解绑」对应设备（或客户自己登录后解绑），新机器用原 CDK 不行（CDK 已核销），应让客户用 `enroll` 接口 + `license_key` 加绑新设备，或后台"重新签发"后让客户端重新激活。

**Q：客户丢了 `license_key`？**
后台「重置许可证密钥」生成新密钥（旧密钥立即失效），或让客户登录后在客户端自助重置。

**Q：能不能一个 CDK 给多台设备用？**
可以，生成 CDK 时把「席位数」设成 N。客户端用 `POST /api/v1/licenses/enroll` 为每台设备占一个席位。

**Q：想按年/永久授权？**
天数字段上限 3650（10 年）；"永久"可设置为 3650 天并在到期前续费。

**Q：需要改端口/加 HTTPS？**
改 `.env` 的 `PORT`（宿主映射）即可。HTTPS 建议在前面放 Nginx/Caddy 反代，并把 `TRUST_PROXY=true`。

**Q：数据库太大/并发高？**
SQLite 单机足够支撑中小规模。高并发或多实例场景建议换成 PostgreSQL（数据访问集中在 `src/store/*.ts`，替换成本可控）。
